# OpenGraffiti 要件定義書 要約版

作成日: 2026-07-25  
対象: 非エンジニア・企画担当・審査関係者向け  
ステータス: MVP要件確定  

詳細は[要件定義書](./要件定義書.md)を参照してください。

## 1. 一言でいうと

OpenGraffitiは、PLATEAUの3D都市モデルにある実在の建物壁面をデジタルキャンバスにし、ブラウザで描いたストリートアートを3Dの街へ反映できるコンテスト用デモです。

作品は上書きされても履歴に残ります。現在表示中の作品は時間とともに退色し、最後は単色の無地面ではなく、選択した建物壁面本来の見た目へ戻ります。

## 2. 利用者ができること

| 主機能 | できること |
|---|---|
| 街と壁を選ぶ | PLATEAUの3D都市を見て、描画対象として登録された壁を選ぶ |
| 描画の下地を選ぶ | 「選択した壁そのもの」または「同じ壁に過去に描かれた作品の、選んだ時点の退色状態」を選ぶ |
| 絵を描く | スプレー、ブラシ、マーカー、消しゴム、色、太さ、不透明度、レイヤーなどを使って描く |
| 3Dで確認する | 公開前に、描いた絵が壁へ正しい向き・大きさで表示されるか確認する |
| 作品を公開する | 描画を3D都市の選択壁面へ反映し、作者名・タイトル・履歴を保存する |
| 壁の歴史を見る | 同じ壁に過去に描かれた作品を時系列で見て、どの作品を受け継いだか確認する |
| 過去の状態から描く | 過去作品が少し消えた状態など、選んだ時点の見た目を固定下地として描き足す |
| 退色を見る | 15秒のデモ表示で、鮮明→色あせ→輪郭のみ→元の壁面、という変化を見る |
| 複数の壁を見る | 道路沿いに設定された複数の壁を「前へ」「次へ」で順番に鑑賞する |

## 3. 描画の大まかな流れ

1. 3D都市から壁を選びます。
2. 描画下地を次の2種類から選びます。
   - **選択した壁**: その壁本来の色・模様・質感をキャンバスにします。現在表示されている作品は引き継ぎません。
   - **履歴から選ぶ**: 同じ壁の過去作品と時点を選び、その時点まで退色した見た目をキャンバスにします。
3. 下地の上に絵を描きます。下地自体を消したり変更したりはできません。
4. 3Dプレビューで壁への反映結果を確認します。
5. タイトルと表示名を確認して公開します。
6. 公開した作品が現在の作品になり、以前の作品は履歴に残ります。
7. 公開作品はデモ時間に沿って退色し、最後は選択した壁本来の見た目へ戻ります。

## 4. MVPの規模と前提

| 項目 | 内容 |
|---|---|
| 対象範囲 | 道路2～3本程度の小規模な街区 |
| 描画壁面 | 基準12面。許容範囲10～20面 |
| 対象壁面 | PLATEAUのLOD2データにある、単純でほぼ平らな壁 |
| 利用端末 | PCの最新版ChromeまたはEdge |
| 描画レイヤー | 固定下地とは別に最大10枚 |
| Undo/Redo | 各5回 |
| 壁ごとの履歴 | デモでは最大20作品程度 |
| 退色デモ | 15秒で4段階 |
| 公開形態 | Web公開を基本とし、会場用のローカル代替手段も用意 |

## 5. 今回実装しないもの

MVPでは、完成するデモを優先するため、次の機能は実装しません。

- スマートフォン向け描画と現地AR表示
- 描画を補助するAI機能
- 画像ファイルの取り込み
- アカウント登録・本人確認
- いいね、閲覧数、滞在時間による人気度計算
- 通報、モデレーション、権限・許可管理
- 決済、スポンサー、運用管理ポータル
- 建物解体後の3Dモデル保存

表示名は作品に保存します。作品を公開できる人は、デモ用の共有トークンで制限します。

## 6. 必要工数

### 6.1 工数の前提

以下は、実装コードがまだない現在の状態から、Codexを回数・トークン・実行時間の制限なく利用した場合に、**人が実際に作業・確認する時間**を人日で表したものです。1人日は8時間です。

Codexが実装、テスト作成、変換スクリプト、調査補助、修正、文書化を担当します。一方、対象エリアの決定、PLATEAUデータの確認、壁の見た目や向きの目視確認、操作性の判断、公開設定、最終受け入れは人が行います。

### 6.2 機能グループ別の概算

| 作業グループ | 最小 | 最頻 | 最大 | 主な内容 |
|---|---:|---:|---:|---|
| 要件最終確認・設計承認 | 0.5 | 1 | 1.5 | 未決事項の決定、AIが作成した設計の確認 |
| PLATEAUデータ・壁面準備 | 7.5 | 11.5 | 18 | 対象選定、1壁面PoC、12壁面の画像・向き・位置確認 |
| 3D都市表示・プレビュー・公開 | 5.5 | 9 | 14 | 3D表示、壁面選択、公開前確認、作品反映 |
| 描画機能・画面の分かりやすさ | 5 | 8.5 | 13 | 描画ツール、2種類の下地、レイヤー、操作導線 |
| 保存・サーバー処理 | 1.5 | 2.5 | 4 | 作品保存、競合防止、再送、エラー復旧 |
| 履歴・退色・デモ操作 | 3.5 | 6 | 9 | タイムライン、過去から描く、退色、状態リセット |
| 複数壁の連結閲覧 | 0.5 | 1 | 2 | 壁の順番と鑑賞位置の調整 |
| テスト・公開・進行調整 | 6.5 | 11 | 17 | 実機テスト、性能改善、デプロイ、リハーサル |
| **合計** | **30.5** | **50.5** | **78.5** |  |

計画上の中心値は約51人日です。三点見積もりによる期待値は約52人日です。

### 6.3 人数別の期間目安

各担当者がCodexを無制限に利用し、週5日稼働する場合の目安です。

| 体制 | 期間の目安 | 最頻の目安 |
|---|---|---|
| 1名 | 約7～16週間 | 約10週間 |
| 2名 | 約4～12週間 | 約7週間 |
| 3名 | 約3～8週間 | 約5週間 |

人数を増やしても、同じPLATEAUデータの確認や統合作業があるため、単純に人数分だけ短くはなりません。

### 6.4 工数が増えやすい条件

- 対象壁面に元の色・模様を取得できるAppearanceやテクスチャがない
- 壁面IDやテクスチャの対応が変換時に失われる
- 曲面、穴のある壁、複数面にまたがる壁も描画対象にする
- 描画対象の壁を12面より増やす
- 認証、人気度計算、ARなど、MVP対象外の機能を追加する
- Codexによるファイル編集、コマンド実行、自動テストが制限される

## 7. 完成と判断する主な条件

- PLATEAU実データの街と描画対象壁面が表示される
- 2種類の下地を選択して描画できる
- 「選択した壁」では壁本来の見た目が下地になり、現在作品が混ざらない
- 履歴下地では選んだ作品・時点の退色状態が各画面で一致する
- 3Dプレビューと公開後の見た目が一致する
- 新しい作品を公開しても以前の作品が履歴に残る
- 作品が退色した最後に、選択した壁本来の見た目へ戻る
- 複数壁を決められた順番で鑑賞できる
- 公開失敗や同時更新でも作品・履歴が壊れない
- 発表用の状態を1分以内に初期化できる

## 8. 実装前に決めること

次の事項は、要件そのものではなく、実装開始前に関係者が決定する必要があります。

- 対象とする都市・街区・PLATEAUデータの年度と版
- 提出期限、担当人数、各担当者が作業できる日数
- 発表に使うPCと会場のネットワーク条件
- Web公開先、画像保存先、データベース

最初に1つの壁だけで「壁面データの取得→2Dキャンバス化→描画→3Dへの再反映」を試し、正しく表示できることを確認してから12壁面へ展開します。
